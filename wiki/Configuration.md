# Configuration

BungeeSK generates a `config.yml` in `plugins/BungeeSK/` on both the proxy and each game server on first start.

## Proxy `config.yml`

The proxy is the **server**: it listens on a port and game servers connect to it.

```yaml
port: 20000               # the port BungeeSK listens on — must be open
password: "AutoGenerated" # shared secret; must match every game server
encrypt: true             # AES-encrypt the connection (leave on)
debug: false
whitelist-ip:
  enable: false           # if on, only the IPs below may connect
  whitelist:
    - "127.0.0.1"
messages: false           # log a line when a client connects/disconnects
files:
  sync-at-connect: true   # push global scripts to a game server when it connects
  auto-update: true       # re-push a global script whenever it changes
  auto-delete: true       # delete a global script network-wide when removed
redis:                    # optional — store global variables in Redis instead of SQLite
  enabled: false          # off = built-in SQLite file (default)
  host: "127.0.0.1"
  port: 6379
  password: ""            # empty = no auth
```

A random `password` is generated on first run — copy it into every game server's config.

> **Redis (optional):** set `redis.enabled: true` to store [global variables](Global-Variables-and-Scripts) in Redis instead of the local SQLite file — useful if several proxies should share them. SQLite is the default and needs no setup. Global *scripts* remain file-based either way.

## Game-server `config.yml`

The game server is the **client**: it connects out to the proxy.

```yaml
connection:
  auto-connect: true               # connect automatically on server start
  address: "127.0.0.1"             # proxy address (127.0.0.1 if same machine)
  port: 20000                      # must match the proxy's port
  password: "AutoGenerated"        # must match the proxy's password
reconnect:
  enabled: true                    # auto-reconnect if the link drops
  delays-seconds: [5, 10, 20, 30]  # wait before each attempt; last value repeats
  initial-delay-seconds: 5         # exponential-backoff fallback (used only if delays-seconds is empty)
  max-delay-seconds: 60            # exponential-backoff fallback cap
  log-attempts: false              # true = log every retry; false = only "lost" / "reconnected"
debug: false
```

### The reconnect schedule

`delays-seconds` is a per-attempt list of wait times. The **last value repeats** for every later attempt:

| `delays-seconds` | Behaviour |
|------------------|-----------|
| `[5, 10, 20, 30]` | 5s, 10s, 20s, then **30s** for every further attempt |
| `[30]` | a **fixed 30s** between every attempt |
| `[]` (empty) | **exponential backoff** between `initial-delay-seconds` and `max-delay-seconds` |

With `log-attempts: false` (the default) you get one **“Lost the connection to the proxy”** message and one **“Reconnected to the proxy.”** message — no per-attempt spam. Set it to `true` to log every attempt.

## Applying changes

Edit `config.yml`, then either restart the server or run the reload command:

- Game server: `/bungeesk reload`
- Proxy: `/bungeeskproxy reload`

New keys are added automatically on load with their defaults; your existing values are preserved. See **[Commands](Commands)**.

> The port and password **must be identical** on the proxy and every game server, or the handshake fails.
